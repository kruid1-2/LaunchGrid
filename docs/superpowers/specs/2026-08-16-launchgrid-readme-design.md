# LaunchGrid README 设计

## 目标

为 GitHub 仓库根目录补充一份中文 README，使访客不进入源码也能理解 LaunchGrid
是什么、当前能做什么、如何构建，以及哪些功能尚未完成。

README 沿用此前 `iPhone Inspector` 的实用型写法：先说明用途和边界，再给出功能、
操作、构建、隐私与已知限制。文案以当前代码和本轮实际验证结果为准，不写未验证的
宣传性结论。

## 文件位置

最终文件为仓库根目录的 `README.md`。项目源码目前位于 `LaunchGrid/` 子目录，构建
命令必须明确先进入该目录，避免 GitHub 访客照抄后失败。

## 内容结构

1. 项目名称、英文名和一句话用途。
2. 已实现功能：本机应用扫描、图标与名称展示、搜索、启动、分页和多显示器定位。
3. 操作方式：点击、横向滚动或触控板、`Command-F`、`Return`、`Escape`。
4. 构建要求与命令：Xcode 工程为当前主入口，列出普通启动和 `--verify`。
5. 项目结构：说明 SwiftUI、AppKit、扫描器、图标缓存、分页渲染和窗口控制器的职责。
6. 本地运行与隐私：无服务器、账户或上传逻辑；只读取普通应用目录并用
   `NSWorkspace` 启动用户选择的应用。
7. 已知限制：没有已签名或公证的发布包，重排、文件夹、全局快捷键和登录项尚未完成，
   GUI 流畅度仍需人工观察。
8. 配置差异：产品目标是 macOS 26，但当前 Xcode 工程部署目标仍为 macOS 13.0，
   `Package.swift` 声明 macOS 26；README 明确记录现状，不假装二者已经统一。

## 表达规则

- 中文为主，保留类名、命令、快捷键和 Apple API 的英文原名。
- 不添加徽章、下载按钮、Release 链接、许可证声明或不存在的截图。
- 不把本地临时签名描述成正式分发签名。
- 不承诺尚未人工验证的视觉一致性或性能结果。
- 构建命令使用仓库中的真实相对路径。

## 验证

- 检查 README 中的本地文件链接和命令路径确实存在。
- 运行 `git diff --check`，确认没有空白错误。
- 重新运行 `./script/build_and_run.sh --verify`，确认文档所列主入口仍可构建并启动。
- 推送后通过 GitHub API 确认根目录存在 README，并核对现有草稿 PR 指向最新提交。

## 完成标准

- GitHub 仓库首页能直接显示项目说明。
- README 的功能描述能在当前源码中找到对应实现。
- README 的构建与验证命令可实际执行。
- 未提交的备份、构建产物和其他项目仍不进入提交。
